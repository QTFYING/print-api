## 五、导出与装载的可复现要点

```bash
# 真生产导出（InnoDB 123 表/59.3MB 走一致性快照；MyISAM 仅 27 表/2.6MB）
# 关键：必须去掉 --routines！该库有中文命名的存储过程 sp_get_tj_cdfp_四舍五入版，
#       mysqldump 8.0 客户端会把名字按 latin1 回传，报 errno 1305 "does not exist"。
mysqldump --single-transaction --quick --lock-tables=false --triggers --events \
          --default-character-set=utf8mb4 --hex-blob --no-tablespaces \
          --databases printingexhibition > live.sql
# 例程/视图改从 information_schema 以文本导出（口径还原只需定义文本）
```

踩过的坑（补记）：
1. **mysqldump 8.0 + 中文例程名 → 失败**，改走 `information_schema.ROUTINES/VIEWS` 文本导出。
2. **mysql 客户端结果转换会把非 ASCII 例程名写成字面 `?`** → 用 `HEX(ROUTINE_NAME)` 反解真实字节后在 PG 侧 `convert_from` 回写。
3. **information_schema 的 `update_time` 会骗人**：118 快照的 `update_time` 停在 6 月，但真正的判据是业务表里的时间戳字段（`applicationdate`/`settime`/`create_time`）——这次就是靠它锁定的。
