## 二、一处建模纠正（影响后续两个域）

**`expo_exhibits_partition`（30 行）不是展馆，是展品品类分区。** 实测其 `name_cn` 为：
数字印前 / 网印印花 / 印刷机械 / 印后加工 / 包装印刷 / 器材耗材 / 标签印刷 / 综合配套及自动化 / 广告喷绘 / 瓦楞纸箱（PC2019 十项）、PC2023 九项「××馆」题材名、PC2027 十一项。

而物理展馆/楼层只存在于 `expo_show` 的横排列里。

`plans/05` §6.1 原文写「`show_hall`（展馆分区，取代 show008~show017_10 横排列 **+ `expo_exhibits_partition`**）」——把两样东西合并成一件了。本次**只把横排列做进 `show_hall`**，那 30 行留给品类树，不混灌。

连带影响两处，需一并纠正：
1. **展商域 `yxzg_id`**：文档记为「意向展馆 → `expo_exhibits_partition.id`」，实际指向的是**品类分区**，所以它应映射到品类树而非 `show_hall`；
2. **`expo_order_types_small.partition_id`** 同理，指向品类分区。

→ 待拍板：品类分区是并入 `product_category`（加 `kind='ZONE'`），还是新建 `show_zone` 表。我倾向**新建 `show_zone`**：它带 `show_id`（每届不同）、`otb_yn/otb_kinds`（收费项关联），与跨届复用的展品类别树语义不同，混在一张表会让品类检索出现同名词跨届混淆。

## 三、疑点清单（原样搬运，未擅自修正）

| # | 疑点 | 证据 | 影响 |
|---|---|---|---|
| S1 | **PC2027 闭展日期 `2027-06-16`** | `show005=2027-04-12`、`show005_1=2027-06-16`，跨 65 天；而 `plans/05` §2 记「展期 2027.4.12–16」 | 疑为月份录入错（06 应为 04）。展期是预登记倒计时、门票有效期、展馆租期的基准，**必须甲方确认后修正**，我们不猜 |
| S2 | **同一列跨届语义漂移** | `show_a1`：PC2019 = `30%`，PC2023/PC2027 = `2023-04-06`/`2027-04-06` | 横排列没有类型约束，老系统按届次挪用列含义。任何按这些列做的报表都必须**分届实现**，不能写一套通用 SQL |
| S3 | 面积四件套语义未定 | `_sq` 恒最大（总面积），`_sq_a/_sq_b/_sq_c` 三者关系未知（如 1号馆：total 12000 / a 8430） | 展位销售统计报表（`sp_get_tj_zwxs`）很可能依赖它们，需甲方说明 a/b/c 分别是什么（已租/可售/公共区域？） |
| S4 | `show018` = 150000（逐届 120000→140000→150000） | 疑为总可租面积（㎡） | 同上，待确认 |
| S5 | `jgyy_year`：PC2027 填的是 **2026** | 与 `code=PC2027` 不一致 | 疑为"协会优惠适用年度"（对应 `JGYYH_Type`），影响折扣计算，需确认 |
| S6 | `venue_name` 仅 PC2027 有值 | PC2019/PC2023 该列为空 | 历届场馆是否同为广东现代国际展览中心？门户展示历史届时会缺字段 |

## 四、验证方式（接手方可直接复跑）

```bash
cd D:\Projects\print-v2\api
node scripts/etl/transform/transform-show.mjs --dry-run   # 预演，不写库
node scripts/etl/transform/transform-show.mjs             # 正式（幂等）

ssh myserver
docker exec -it postgresql psql -U user_PcxZwh -d pte_platform_dev
  select code, name_cn, start_on, end_on, is_current from "show" order by code;
  select count(*) from show_hall;                              -- 45
  select hall_key, hall_no, name_cn, areas from show_hall
    where show_id=(select id from "show" where code='PC2027') order by sort_order;
  -- 唯一性：current 届必须恰好 1 个
  select count(*) from "show" where is_current;
```

已验证的三件事：
1. **零丢失**：PC2027 的 94 个非空列全部落入 A(8 主表)/B(17 展馆名)/C(41 图与面积)/D(1 旧主键)/E(27 未定语义→JSONB)，无未归类项；
2. **幂等**：连续两次执行，`show=3 / show_hall=45` 不变，`(show_id,name_cn)` 重复 0；
3. **约束生效**：`is_current` 部分唯一索引保证当前届唯一。
