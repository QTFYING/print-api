# 迁移 ETL 纪律

## 适用场景

- 新增或修改 `scripts/etl/**`
- 某域 transform（展商、合同、财务、观众、资料、会员）
- 对账、脏数据体检、字段映射登记

## 全局规则入口

`docs/architecture/data-migration-five-step.md` 是流程事实源；`AGENTS.md` 第 5 节是边界。

## 三条硬纪律

1. **零丢失必须可证明**，不是"应该没丢"。
   - 每域输出"旧表非空列 → 去向"的逐列归属统计，出现"未归类"即为漏项。
   - 装载后与生产逐表 `COUNT(*)` 基线对账（`--baseline`），差异必须归零或书面归因。
   - 存疑/未定语义列一律进 `legacy_extra` JSONB，不猜、不丢。
2. **幂等可续跑**。远程隧道会被随机 reset（实测多次）：
   - 台账中行数已一致的表跳过；其余先 `DROP TABLE IF EXISTS ... CASCADE` 再建再灌。
   - 单表失败只记 `etl.load_error`，不回滚已成功的表。
   - 外层可循环跑到收敛，不要求一次成功。
3. **脏数据不猜语义**。空串、`0000-00-00`、千分位、NUL、多值逗号串一律先出体检报告（`etl.column_profile` / `etl.comma_scan_hit`），规则写进 `notes/04`，未定项进 `notes/02` 待甲方。

## 技术口径

- **副本层列一律 `text`**：MySQL 允许 int 存空串、date 存 `0000-00-00`、text 存 `0x00`；保类型会让 COPY 中途炸且难定位。
- **NUL 处理**：PG 的 `text` 不接受 `0x00`，转成可逆标记 `\x00` 并在 `aggregates.nul_replaced` 记数量。
- **解析与写库分两阶段**：绝不在 `for await` 读流循环里 `await` 写库 —— 实测会让同一文件跑出两种行数。
- **流完整性校验**：dump 必须含 `-- Dump completed`，缺失直接拒绝装载（退出码 4），不把截断当成功。
- **列名/字面量**：给 PG 生成 SQL 时，标识符用双引号、字符串字面量用单引号，别把 `JSON.stringify` 的双引号当字符串用；`group` 等保留字必须加引号。
- **裸 SQL 插入要自带 id**：Prisma 的 `@default(uuid(7))` 是客户端生成，DB 层无默认值。
- **外键删除按依赖倒序**：Prisma 生成的是 RESTRICT 外键，顺序错就删不掉。
- **不造业务样例数据**：工具自测件跑完即清并明确标注为自测。

## 必做顺序

1. 先查副本层真实数据与画像，再定清洗规则（不读代码猜口径）。
2. 写脚本 → `--dry-run` 预演（只看解析行数与归属统计，不写库）。
3. 正式执行 → 逐表对账输出 → 台账落 `etl.*`。
4. 中断就重跑，直到"失败 0 表 + 对账一致"。
5. 结论写进 `notes/`，疑点写进 `notes/02`，不在代码注释里留待确认项。
