# 工作接力

## 适用场景

- 一个没做完的章节要换会话继续
- 现场交付任务要交给另一位 FDE 或另一个代理
- 长时间任务在压缩上下文前需要留档

## 全局规则入口

`AGENTS.md` 第 9.2 节的提交与验证口径同样适用于接力文档；本 skill 只规定"写什么"。

## 文件位置与命名

- `notes/handoffs/YYYYMMDD-<主题>.md`，模板见 `notes/handoffs/_template.md`
- 日期写绝对值，不写"今天/昨天"
- **接力文档是快照，不是事实源**：它指向事实源，不取代事实源，不复制大段代码

## 写作要求

1. **区分"已完成（可信任）"与"未验证"**：没跑过验证的事不许写进"已完成"，要么进"未完成"，要么单列风险。
2. **环境快照要能复现**：分支/commit、端口、隧道命令、装包命令、DSN 形态（不写值）、在跑进程与停法，照敲就能起。
3. **指针指向事实源**：给文件路径 + 章节/函数名，不抄内容。
4. **待拍板决策单独成节**：写清谁定、定什么、影响、我的倾向，别让接手方猜。
5. **写"已排除项"**：试过不行的路、被推翻的判断、别再回头走的假设 —— 这是接力文档最值钱的部分。
6. **边界提醒**：不动的库/服务/文件、不提交的凭据、不该改的既有约定。

## 必做顺序

1. 复制 `_template.md` 起稿。
2. 现场取真值：`git status --short`、`git log --oneline -3`、健康检查输出、对账输出，写进文档而不是凭记忆。
3. 按模板十节填，重点在「已完成（带验证方式）」「未完成/下一步（可直接开工的粒度）」「已排除项」「待拍板」。
4. 顶部标注当前状态；章节闭环后标"已闭环 + 日期"或归档，避免 handoffs 堆积误导后来人。
5. 若涉及凭据：只写变量名与形态，绝不写值。
