# 质量保障与结论口径

## 适用场景

- 任何"我改完了 / 我验证过了"的表达之前
- 结论被质疑、发现与自己先前说法冲突时
- 章节收尾、提交前

## 全局规则入口

`AGENTS.md` 第 9 节为准。

## 验证口径

| 改动类型 | 最小验证 |
|---|---|
| 结构/装配 | `pnpm typecheck` |
| 运行链路 | `pnpm dev:server` + `GET /api/v1/health` + 目标接口实测 |
| 数据模型/索引 | `pnpm db:migrate`（含 ensure）+ `node scripts/dev/smoke-schema.mjs` |
| 鉴权/RBAC | `node scripts/dev/smoke-auth.mjs`，且**连跑两轮**验证自隔离 |
| ETL/清洗 | `--dry-run` 预演 + 正式逐表对账 + 逐列归属无未归类 |
| 契约 | `pnpm openapi:export` + 前端 `pnpm contract:sync` 生成物 diff 符合预期 |
| 收尾 | `pnpm lint`、`pnpm format` |

不能运行的验证项，必须在交付说明里写明：**未执行什么、当前停在哪、剩余风险**。

## 结论表述纪律

1. **区分"实测"与"推断"**。每条结论给可验证来源（文件+行号、SQL 输出、命令结果）；查不到就明说"未检索到"，不预设结论。
2. **不凭印象写技术结论**。官方文档查不到的标"待核实"。
3. **错了要当面收回并说明真实根因**，不得悄悄改掉。本项目已有两例：把端口串台误判成"别人改我们账号"；用列名启发式探测脏数据导致误报"金额无千分位问题"。
4. **归因前先查自己动过什么**。认证失败先核对端口归属与隧道落点，不要先怀疑外部、更不要反复轮换凭据。
5. **判据要选对**：判断实例新旧看业务表时间戳字段，不看 `information_schema.update_time`（会骗人）；判断脏数据做全列扫描，不按列名猜。
6. **"代码改完" ≠ "任务完成"**：未验证、未同步文档、未过门禁的，一律写在"未完成"里。

## 测试自隔离要求

- 会改共享状态的断言（授权、唯一键、锁状态），**前置归零 + 事后清理都要做**，只靠 `finally` 不算隔离。
- 测试账号统一用可识别后缀（`@smoke.local`），便于兜底清理。
- 一条断言如果只在"干净环境"下才成立，说明它测的是环境而不是规则 —— 补前置归零。
